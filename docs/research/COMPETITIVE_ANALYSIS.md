# Competitive analysis and reuse decisions

Research date: **2026-11-24**. This is a desk review of official public product, pricing, licensing and support pages, not a hands-on usability study or an independent audit of vendor data quality. All links below were accessed on that date. Product plans can change, promotional prices are deliberately omitted, and the cited terms must be rechecked before an integration or public data distribution is enabled.

The strongest opportunity for TechPulse is a local research workflow that connects independent evidence, records missing and contradictory evidence, and permits abstention. Competing products already provide capable charts, screeners and alternative datasets; merely reproducing their navigation would not establish comparable coverage or forecasting validity.

## Usability findings and scope of inference

These are design hypotheses derived from advertised workflows, not measured defects in the products:

- Subscription tiers, exchange entitlements, API plans and legal data rights are different things. TechPulse should expose coverage and source health at the point of analysis, not merely in a settings screen.
- Charting tools make pattern exploration easy, but visual resemblance does not validate future performance. Show detection rules and data sufficiency, and reserve probability-like confidence for independently evaluated models.
- A research candidate should have a short evidence trail: observed facts, source times, missing fields, supporting and contradictory considerations, conditional entry, horizon, invalidation and risks. Political transactions or options activity alone must never establish a buy recommendation.
- Delayed reports should be evaluated from when the information became available, not retroactively from the original transaction date. Government ceiling values should not be used as realized revenue.
- Dense dashboards can support experienced users while remaining comprehensible through sorting, search, focused details, tooltips and readable empty states. Keyboard access, contrast and light/dark themes need actual GUI checks.
- No comparative claim about competitor speed, reliability, profitability, security or accessibility is established by this review. Those require independent measurements.

## Open-source reuse and dependency licensing

### OpenBB: pin the exact artifact

The official **v4** licensing FAQ describes an AGPL transition, while the current repository `develop` LICENSE says **Apache-2.0**. The repository's develop HEAD resolved through GitHub to `f0f1852b96dd3fc4d5868f8863cbe053ff49c6cd` during this review. This is version-specific evidence, not a conclusion that every OpenBB package, historic release, provider or hosted product shares one license. [v4 licensing FAQ](https://docs.openbb.co/odp/v4/python/faqs/license), [LICENSE at inspected commit](https://github.com/openbq-org/OpenBB/blob/f0f1852b96dd3fc4d5868f8863cbe053ff49c6cd/LICENSE).

Decision: do not copy or embed OpenBB in the initial preview. Its adapter architecture is useful precedent. Before later reuse, pin a release, inventory actual file/package licenses and notices, preserve required attribution, examine transitive dependencies and record upstream data terms independently. Apache-2.0 code can generally coexist with MIT project code under its own conditions; an AGPL component needs a separate distribution/network-use assessment. Neither software license grants market-data rights.

### Qt / PySide6 distribution

Qt for Python has open-source and commercial licensing paths; individual bundled modules and third-party components can have separate licenses. Qt's official LGPL guidance requires, among other things, notices/license text, corresponding library source or a compliant source offer, and the user's practical ability to replace/relink and run the library. Some Qt modules are GPL-only. [Qt LGPL obligations](https://www.qt.io/development/open-source-lgpl-obligations), [Qt for Python licenses](https://doc.qt.io/qtforpython-6/licenses.html).

Decision: dynamically linked Qt libraries, a minimal module set, shipped notices and a recorded corresponding-source/replacement procedure are release gates. An MIT license for TechPulse's own code does not relicense Qt. A successfully built executable is not by itself a completed licensing or clean-machine release audit.

### Other components

Reuse established numerical/chart libraries where they reduce errors and justify their footprint, but inventory the exact locked distributions before shipping. Straightforward deterministic indicators may use small, tested formulas without a full financial platform dependency. Tests of formulas are not evidence that technical signals predict returns. No proprietary chart scripts, copied portfolio allocations, logos or restricted source datasets are required.

## Initial delivery implications and unresolved gates

An honest first release can provide a native offline shell, fictional demonstration mode, validated authorized imports, optional direct official-provider adapters, deterministic indicators, evidence-aware scoring, local watchlists/paper tracking and source-bearing reports. Missing free options coverage, point-in-time fundamentals, lawful political collection and redistribution clearance, international contractor mapping and calibrated forecasts must remain explicit limits.

Acceptance for future competitor-related claims: revisit the primary pages, record a date and tested workflow, and do not use paid product marketing as evidence that TechPulse has equivalent data, rights or results. The data-provider research document owns exact API quotas, retention decisions and official political-source restrictions; the technical research document owns academic validation methodology.
